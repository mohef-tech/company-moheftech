LATAR BELAKANG PROJECT
====================================================================

Tujuan awal:
- Awalnya rencana hanya untuk catatan tarif pribadi (pengganti excel),
  supaya saat client tanya harga (POS kasir, aplikasi gudang, servis
  laptop, dsb) tidak perlu buka-buka catatan manual.
- Berkembang jadi: catatan pribadi tsb dibungkus jadi company profile
  yang bisa dikirim ke client, sekaligus punya potensi menjaring
  client baru yang menemukan website secara organik (bonus, bukan
  tujuan utama).

Prioritas pengguna (urutan penting):
1. Admin (pemilik/Hendra) - pengguna paling sering, dari LAPTOP.
2. Client yang dikirimi link - sudah kenal/bertanya, dari HP.
3. Pengunjung publik yang menemukan sendiri - bonus.

Prinsip utama yang disepakati:
"Jangan membangun infrastruktur untuk masalah yang belum dimiliki
Mohef Tech."

CATATAN & KEPUTUSAN PENTING (kronologis)
====================================================================

1. REVIEW PRD AWAL (V1)
   - PRD awal sudah disiplin soal scope, tapi ditulis seolah
     pengunjung asing adalah pengguna utama.
   - Ditemukan beberapa kontradiksi: data ganda (profil vs
     konfigurasi), autentikasi tidak konsisten (tabel Admin vs
     environment variable), 3 flag lokasi yang tumpang tindih,
     siteStatus yang tidak jelas gunanya.
   - Celah: tidak ada portfolio/bukti kerja, tidak ada link per
     layanan, format nomor WhatsApp berisiko salah format untuk
     wa.me link.

2. KLARIFIKASI TUJUAN ASLI
   - Owner menjelaskan tujuan sebenarnya: catatan pribadi + alat
     kirim ke client, bukan situs marketing untuk publik.
   - Dampak: SEO diturunkan prioritasnya (realistis client baru
     datang dari rujukan/WA/Google Business Profile, bukan dari
     pencarian organik satu halaman ini).
   - Link per layanan + preview WhatsApp naik jadi fitur inti,
     karena itu cara utama owner "mengirim" jawaban ke client.

3. MODEL HARGA - HARDWARE VS SOFTWARE
   - Hardware: harga PASTI (mis. install ulang Rp100.000, ganti RAM
     4GB/8GB beda harga). Di luar itu jasa, sparepart terpisah.
   - Software: harga MULAI DARI, tapi TIDAK bisa dipatok per jenis
     aplikasi (karena permintaan client sangat beragam: kasir,
     gudang, ticketing, chatbot, penjadwalan instansi, dsb - tidak
     bisa diprediksi semua kemungkinan).
   - Keputusan final: software dihargai berdasarkan TINGKAT
     KOMPLEKSITAS (Sederhana / Menengah / Kompleks), bukan jenis
     aplikasi. Ditambah modul tambahan berharga sendiri.
   - Konsekuensi ke data model: satu layanan bisa punya BEBERAPA
     opsi harga (bukan satu harga tunggal). Struktur ini melayani
     baik varian hardware maupun tingkat software sekaligus.

4. PAKET / BUNDLING (dibahas, keputusan: ditunda)
   - Sempat dibahas ide paket ala IPOS (Desktop Offline, Web Local
     Server, Hybrid, Cloud Full) untuk aplikasi kasir.
   - Model SaaS/langganan multi-tenant DITOLAK untuk sekarang -
     aplikasi kasir owner dibuat untuk 1 client (cafe), bukan
     dirancang multi-tenant. Menjual sebagai SaaS sekarang berarti
     janji yang belum ada fondasinya.
   - Paket Hybrid (offline+sync cloud) DITOLAK dari V1 - paling
     rumit secara teknis, masuk kategori Custom/Konsultasi saja.
   - Keputusan akhir: TIDAK ada paket kaku, owner tetap develop dari
     nol sesuai permintaan client (lebih sesuai gaya kerja owner).

5. PORTFOLIO
   - Owner ternyata sudah py banyak project nyata: POS kasir (Flutter),
     Mohef Assessment, Mohef Masjid (display jadwal sholat TV masjid),
     Mohef Ticketing, Mohef Chatbot, Company Profile PMII Sidoarjo,
     Sistem Gudang Clarice, Sistem Pembayaran SPP, Penjadwalan
     Samapta Polres Mojokerto.
   - Ini bukti kerja yang kuat, lebih meyakinkan client software
     daripada tabel harga. DITAMBAHKAN ke V1 (sebelumnya ditunda ke
     V2 di PRD awal).
   - Aturan: proyek instansi/client HANYA ditampilkan dengan IZIN.
     Kalau ragu/belum izin, ditulis generik.

6. ADMIN & SUPER SIMPLE

     memang dinamis dan terus bertambah sesuai permintaan.
   - Ini mengonfirmasi keputusan pakai dashboard + database, bukan

   - Login admin: USERNAME TEKS BIASA (bukan email, mis. "mohammed")

11. TECH STACK - EVALUASI
    - Stack awal: Next.js + TS + Tailwind + Prisma + PostgreSQL +
      Auth.js + Vercel. Dinilai 90% sudah pas.
    - Auth.js diganti custom auth (lihat poin 6).
    - DITEMUKAN MASALAH: Vercel Hobby (free) SECARA EKSPLISIT
      melarang penggunaan komersial. Website ini menghasilkan lead
      untuk layanan berbayar = komersial = butuh Vercel Pro
      ($20/bulan).
    - Owner mau tetap gratis (no budget untuk hosting berbayar).
    - Riset alternatif: Netlify Free & Cloudflare Pages Free
      SAMA-SAMA MENGIZINKAN penggunaan komersial (beda dari Vercel
      Hobby).
    - Cloudflare Pages ditolak: fungsi server jalan di Workers
      runtime (bukan Node.js penuh), berpotensi bikin Prisma/database
      connection lebih ribet.
    - KEPUTUSAN FINAL: pindah hosting ke NETLIFY (free, commercial
      use diizinkan, dukungan resmi untuk Next.js, stack lain tidak
      perlu berubah).
    - Catatan: kebijakan free-tier platform bisa berubah sewaktu-
      waktu, perlu dicek ulang saat implementasi.

12. PRD v1.1 SELESAI DISUSUN
    - Semua keputusan di atas dirangkum jadi 1 dokumen bersih:

    - Owner sudah setuju ("overall aman").

13. ISU TEKNIS: PRISMA v7 vs v6 (ditemukan saat setup project)
    - `npm install prisma` secara default terpasang versi 8.0.0-rc.17
      (release candidate, belum stabil) yang ternyata sudah berubah
      total jadi "Prisma Developer Platform" - CLI baru yang gabung
      dengan platform hosting Prisma sendiri (project, deploy,
      service, postgres, bucket, dll). Perintah classic seperti
      `generate` dan `db pull` TIDAK ADA lagi di versi ini.
    - Di versi 7 ke atas, `url`/`directUrl` di schema.prisma dihapus
      total, harus pindah ke prisma.config.ts, dan PrismaClient wajib
      pakai "adapter" eksplisit saat runtime. Ini perubahan arsitektur
      besar, bukan cuma sintaks.
    - KEPUTUSAN: PIN ke Prisma versi 6 (stabil, classic), bukan ikut
      versi terbaru yang masih berubah-ubah:
      npm uninstall prisma @prisma/client
      npm install prisma@6 --save-dev
      npm install @prisma/client@6
    - Dengan v6: url/directUrl kembali bisa ditulis langsung di
      schema.prisma datasource block, tidak perlu prisma.config.ts,
      tidak perlu adapter eksplisit untuk PrismaClient.
    - PELAJARAN: ke depan, kalau install ulang dependency di project
      ini (misalnya di komputer/environment baru), SELALU pin versi
      Prisma ke v6 secara eksplisit (`prisma@6`, `@prisma/client@6`),
      jangan biarkan npm ambil versi "latest" secara default.
